### שלושה עקרונות מעל הטבלה

1. **לכל עובדה בית אחד.** לפני כתיבה מאתרים את קובץ הרשות (מפת הרשויות ב-README הראשי)
   ומעדכנים **אותו**, במקום. קובץ חדש נפתח לנושא חדש — לא ליום חדש.
2. **חי נפרד מהיסטוריה.** מסמך חי (סקיל, ממצאים, README) משקף את האמת של עכשיו;
   יומן מתוארך (שיעורים, ביקורות, מסירות) לא נערך לאחור. כשהאמת משתנה — מתקנים את החי,
   רושמים את ההפרכה, ומשאירים את ההיסטוריה כמות שהיא.
3. **תיקייה חדשה בשורש = החלטת מבנה, לא תוצר-לוואי.** היא נפתחת רק בקומיט שמעדכן גם את
   ה-README הזה וגם את רשימת ההיתר בשומר — ובשינוי גדול, שואלים את אמיר קודם.

### מסלולי העבודה הקבועים — נוהל שלם לכל סוג פעילות

*אלה הפעילויות שאמיר קבע (12/08/2026) שימשיכו ללוות אותנו. לכל אחת נוהל קבוע מראש —
מהרגע שהיא מתחילה ועד מה שסוגר אותה.*

**🎓 מסלול 1 — שיעור עם אמיר (מצב למידה, דוגמת שיעור 4):**
1. לפני: תיק הכנה `lessons/LESSON-N-PREP.md` — מה הולכים ללמוד ואילו שאלות פתוחות.
2. במהלך: צפייה ורישום. שאלות נאספות לסוף — לא שוברים לאמיר את הזרימה.
3. אחרי, באותו יום: יומן שיעור ב-`lessons/` · המודל ב-`projects/lesson-N/` · לקח שמשנה
   התנהגות מוטמע **בסקיל** (המסמך החי, לא רק ביומן) · שורה בצ'ק-ליסט של PROGRAM.
4. מבחן אם אמיר נותן → הציון והפערים נרשמים. שומר → קומיט → פוש.

**📐 מסלול 2 — למידת מודל קיים (דוגמת שיעור 2):**
1. קריאה ומדידה של המודל מבפנים (הכלל הקבוע: המספרים שייכים למודל הזה — **השיטה** כללית).
2. הבנייה/ההעתקה במודל נפרד ב-`projects/<שם>/` — לעולם לא בקובץ של אמיר.
3. "בוצע" רק אחרי שערי קבלה נמדדים: ספירות, משקל, כפילויות, `vfy_fit` — לא צילום מסך.
4. ביקורת או ציון של אמיר סוגרים. הלקחים מוטמעים בסקיל. שומר → קומיט → פוש.

**📖 מסלול 3 — המדריך פרק-פרק (הנוהל הרץ):** ההגדרה המוסמכת = טבלת חמשת השלבים של
אמיר ב-PROGRESS (ראש חלק ד). בקצרה: פרק → הערות ב-`manual/<אות>/` → רצועה במודל →
שורת PROGRESS + שומר → קומיט → פוש.

**🔬 מסלול 4 — מחקר הנדסי:** שאלה מוגדרת → תיקיית `research/<נושא>/` → המסקנות
האופרטיביות מוטמעות בסקיל ובידע → הצגה לאמיר.

**🧪 מסלול 5 — מבחנים ובדיקות API (יהיו הרבה):**
- **מבחן מאמיר:** שערי הקבלה נגזרים מהשרטוט/הדרישה **לפני** שמתחילים · המודל בתיקיית
  ה-`projects/` המתאימה · ההגשה רק אחרי אימות עצמי מדוד · ציון אמיר והפערים נרשמים.
- **בדיקת יכולת API:** לפני כל ניסוי — ‏`THE-CEILING` ו-`LETHAL-CALLS` (לא לחזור על מה
  שכבר נמדד) · הניסוי ברצועה במודל למידה, לעולם לא בקובץ של אמיר · כל ניסיון עטוף
  ביומן (`mark()`/`problems()`) · **כל תוצאה נרשמת בקובץ הרשות — גם כישלון: מבוי סתום
  מדוד הוא ממצא ששווה כסף** · מה שניתן — קריאה בחזרה מהמודל, לא הנחה.

**🏗️ מסלול 6 — פרויקט לקוח אמיתי (נולד 13/08/2026, ‏MARTAR):** שרטוט מגיע מהלקוח ואף אחד
לא יודע את התשובה מראש.
1. **קוראים את השרטוט כגיאומטריה ולא כתמונה** — מחלצים את הווקטורים מה-PDF, מתאימים קנה מידה
   בתוך מבט אחד, ורק אז מודדים מה שלא מסומן. הנוהל: `reading-supplied-drawings.md` בסקיל.
2. **מוכיחים את הקריאה לפני שבונים** — מול המשקל המוצהר בשרטוט, מול שרשרת מידות שחייבת
   להסתכם, ומול סימטריה. קריאה שגויה של אלמנט מתגלה כאן, לא אחרי 50 חלקים.
3. **מה שהשרטוט לא אומר — שואלים שורה אחת.** אופן ההרכבה (על איזה פן יושב פרט) הוא הפער
   החוזר, ואסור לממצע בין שתי קריאות. ⛔ ניחוש שמוצג כעובדה = חלק מיוצר שגוי.
4. המודל ב-`projects/<שם-הפרויקט>/` עם ‏README שמצטט את נתיב השרטוט אצל הלקוח; שערי קבלה
   נמדדים (ספירה פר-מחלקה · חורים פר-חלק · התנגשויות · משקל מול המוצהר) → שומר → קומיט → פוש.

**🔀 מסלול 7 — עבודה על כמה מודלים במקביל (נולד 17/08/2026, בהוראת אמיר):** הוא עובד על
פרויקט אחד בזמן שהסוכן עובד על אחר, ולסוכן עצמו כמה מודלים עם משימה נפרדת לכל אחד.
1. **נכנסים למודל במפורש ויוצאים ממנו במפורש.** ‏`eb_api.use(<dwg>, task=...)` · ‏`with
   eb_api.model(<dwg>):` · ‏`eb_api.open_model(<dwg>)` למודל שני באותו AutoCAD.
   ‏**מודל שלא נכנסו אליו = אין אופ**, וזה מכוון.
2. **מודל של אמיר מוכרז:** ‏`python app/worksession.py claim "<dwg>"` ⇒ הסוכן מסרב לו אופ,
   סירוב לסגור אותו, וסירוב אפילו להחליף ממנו את התצוגה. גם שרטוט **לא רשום** בחזית מוגן.
3. **לכל מודל תיבת דואר משלו** (`app/plugin/ch/<slot>/`) — הפקודה, התוצאה וכל ~40 קובצי הפלט.
   ‏השדה `slot` נגזר מהשרטוט **בשני הצדדים** ולכן אין מה לתאם.
4. ⛔ **מגבלה שנמדדה:** רק **מופע AutoCAD אחד נגיש ל-COM** בכל רגע — המוקדם שעדיין חי. ⇒
   ריבוי המודלים של הסוכן חי **בתוך מופע אחד** (שיוך ואז ירי, בנעילה), ומופע שני של אמיר
   בטוח פשוט משום שאי אפשר להגיע אליו. הפירוט: `knowledge/learning/findings/PARALLEL-MODELS.md`.
5. סגירה: ‏`worksession.py close` בסוף העבודה על מודל — משמרת פתוחה שנשארת מאתמול תסרב מחר.

**⚖️ חוק-העל לשיטות חדשות:** כשאמיר מביא דרך התפתחות שלא הכרנו — הצעד הראשון אינו
העבודה אלא **הגדרת המסלול**: שורה בטבלת הניתוב + נוהל קצר בסעיף הזה + (אם נדרשת
תיקייה חדשה) עדכון רשימת ההיתר בשומר, הכל בקומיט אחד. רק אחר כך מתחילים לעבוד.
כך שיטה חדשה אף פעם לא מייצרת בלגן חדש.
