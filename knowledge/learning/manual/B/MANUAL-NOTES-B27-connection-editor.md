# B.27 Connection Editor — chapter notes

*Read end to end 09/08/2026, pages 361–363 (fulltext lines 8543–8640).*

> *"ProSteel permits you to **edit and exchange all connections** of a construction in a comfortable
> and clear way."*

Select the parts whose connections you want; they are shown in one marking colour and **everything
else is hidden**. Any connection between the selected parts appears as a **coloured 3D-arrow
symbol**, and picking the symbol selects the whole connection — *"you avoid having to look for the
connection via the shape properties."*

⚠️ *"the modifications will not be valid before **re-opening of the command for a second time**."*

## Group Display / Group Options

`Length` and `Diameter` size the 3D arrow. ⭐ *"The direction of the arrow shows **from the connected
part to the component to which it was connected**"* — so the arrow encodes the joint's direction.
`Colour` is for the *surrounding* construction: pick a weak one, *"the symbols themselves are
displayed in green, red and yellow."*

`Hide…` hides work frames and structural elements — ⭐ **"Bolts are always hidden."**
The three families that can be shown as symbols:
- **Standard Connections** — end plates and the rest, built into ProSteel
- **Cut Connections** — cuts at objects, mitred cuts
- ⭐ **COM-Connections** — *"all external connections realized via the **COM-PlugIns**"* — **these are
  the 62 `PSN_*` macros found in B.24.** The editor is where they surface.
- ⭐⭐ **`Delete with`** — *"when a connection is deleted, all attached parts generated by this
  connection will be **deleted as well**."*

## The three commands

- **DELETE** — *"remove the selected connections completely, i.e. all component parts and
  processing actions created by means of these connections will be deleted as well."*
- **EDIT** — opens that connection's own dialog.
- ⭐⭐ **CLONE** — transfer one connection's settings to others, and *"it is also possible to
  **change the connection type** if this is reasonable (e.g. you can replace a **plate connection by
  a web angle connection**)."* Pick the source first; *"all connections **not being able to seize
  these data are hidden**"*; then pick the targets.

## ⭐⭐⭐ Verify Connections — the QA gate

> *"all connections are verified with regard to **collisions and marginal distances** before being
> displayed as symbol."*

| colour | meaning |
|---|---|
| 🟢 Green | the connection is correct |
| 🟡 Yellow | **the hole distances are not observed** |
| 🔴 Red | **the connection has collisions** |

⇒ That is precisely the audit this project keeps performing by hand — and yellow is exactly the
class of defect found in B.22 (holes without bolts) and B.26 (rows 50 mm apart).

## Edit Single Connection
Right-click a part → **MODIFY CONNECTION**. ⚠️ *"This entry doesn't exist if the part has **no or
several** connections."*

# MEASURED 09/08/2026

## The API

| dialog | API |
|---|---|
| the symbol's status | `PsEditConnection.Status` |
| its type | `PsEditConnection.LinkType` → **`LogicalLinkType`, 42 values** |
| COM-Connections | `PsEditConnection.COMIdent` |
| the arrow's direction | `OwnerId` → `TargetId` |
| arrow size | `setDiameter` / `setMinLength` |
| **DELETE + `Delete with`** | ⭐ **`PsEditLogicalLink.RemoveLogicalLinkByNumber(n, DeleteParts)`** |
| delete them all | `RemoveAllLogicalLinks(DeleteParts)` (+`…2(…, Verbose)`) |
| EDIT | `EditThisLink(n)` |
| the inventory | `PsLogicalLink` — `getTargetId`, `getBoltObjectId(n)`, `getLinkObjectId(n)`, `getAdditionalObjectId(n)`, and a `Get…LinkData()` for **every** connection family |

⭐ `LogicalLinkType`'s 42 values are the vocabulary of a model audit: `kCuttedByLink`,
`kHolesFromLink`, `kCopedByLink`, `kPlateConnectionLink`, `kConnectWithWebAngle`,
`kConnectToBracing`, `kBoltedLink`, `kStiffenerLink`, `kEndplateSplice`, **`kCOMLink`**, …

## ✅ `connkill` — the removal B.26 needed

```
connkill handle=C7B number=all deleteparts=1   ->   links 1 -> 0
```
⇒ **This is what B.26 was missing.** There, deleting a connection's *parts* left the link alive and
the next attempt reported `parts +0`, because ProSteel still believed the joint was there.
`RemoveLogicalLinkByNumber` removes the joint itself.
ⓘ In this instance `deleteParts=1` did **not** change the census — the link went, the geometry
stayed. Whether the flag removes parts in other cases was not established here.

## ⚠️⚠️ And an audit that had to be RETRACTED

`connverify` was written to walk every part, read each link's **type**, **bolts** and **generated
parts**, and flag mismatches — B.27's yellow light, automated. Its first run reported:

```
parts=321  withLinks=74  links=98  flagged=32
```

**Every one of those 32 flags was false**, and the run had to be corrected:
- **`LinkType` always read `kUndefinedLink`** — `PsEditConnection` has **no binder**, so a fresh
  instance just reports its default. There is no way to ask "what type is *this* link".
- **`getBoltObjectId(0)` and `getLinkObjectId(0)` returned 0 on every link**, so bolts and parts
  always counted zero.
- ⇒ so `HOLES-NO-BOLTS` only ever meant *"this part has holes"* — and it flagged the **B.22
  purlins, which carry 23 bolts measured through COM**.

The op now reports `detailUnread` instead of a verdict, and says in its own result line that link
type and bolts are not readable from this API.

⇒ **The real lesson, and it is the same one as the bounding boxes and `dumpmodel`: an audit is only
as honest as its instrument.** A verdict column that cannot fail looks like knowledge and is
noise. **Judge a connection by GEOMETRY** — bolt positions against hole positions, the way B.22 and
B.25 were judged — not by an API field that returns a default.

## What IS reliably readable

`PsEditLogicalLink.SetObjectId(id)` + `get_LogicalLinkCount()` works: over the bands built today
(x 200000–400000), **321 parts, 74 of them carrying 98 logical links**. That much is real, and it
is enough to find every part that participates in a joint.
